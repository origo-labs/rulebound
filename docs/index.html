The usual fix for an agent that will not stop is a model above the model. We tried that.

Every supervisor built so far returns a binary result. A binary result cannot distinguish the work is wrong from the check could not run. That distinction was learned the expensive way: a predecessor verifier that failed to start, and one whose tests failed, were indistinguishable to its caller — which confounded every measurement made through it.

A 400M span classifier and a frontier LLM both saturated on the same head, and the classifier flagged rule violations on states where the diff was empty. The rules in question were "standard library only" and "never delete a test" — trivially machine-checkable. So the quality bar became an executable contract, and the instrument runs the contract instead of forming an opinion.

02 — results of inspection

Rulebound refuses to report a gate as passed when the gate did not run.

Four possible results, and one of them is not a stricter no.

RefResultExitMeaning
R-01 ACCEPT 0 Every enabled gate ran, and passed.
R-02 BLOCK 1 One or more error-severity findings, each carrying its evidence.
R-03 ESCALATE 3 Something wants a human. Nothing is blocking.
R-04 ERROR 2 No verdict was reached. A gate could not run.
Note on R-04 Exit 2 is not a stricter exit 1. A gate that could not run has not passed, and a contract that could not be read has not been violated.

Across 240 replays, 0 returned ERROR — not because the code is sound, but because the two failure modes are no longer the same event.

03 — inspection checklist

What can be checked, and what will not pretend to.

☑ dependency_surface_unchanged Did a production dependency, feature, or default-features change? inspect
☑ tests_not_deleted Did a test disappear, or gain #[ignore]? inspect
☑ public_api_unchanged Did a public item's signature change or vanish? inspect
☑ unsafe_surface_unchanged Was unsafe surface added? inspect
☑ suppressions_not_widened Was an #[allow] added, or broadened to a whole tool? inspect
☑ paths_unchanged Was a frozen path touched? inspect
☑ checks_green Do fmt, clippy and test pass? inspect
☑ external_tool What did a third-party gate say? slop-gate verified inspect
◈ contract_not_loosened Did this diff weaken the contract without saying why? locked
◈ contract_review_stale Is the review date still fresh? locked
⊘ secret_absent Credential-shaped strings in the diff? refuses
⊘ judged Is this change on-topic for the job? escalate-only refuses
On the two locked items They cannot be declared and they cannot be removed. Both were originally declarable — and a worker deleted the declaration, and got ACCEPT.

A gate that can be switched off by the thing it guards is not a gate.
On the two that refuse A contract that asks for an unavailable check fails loudly. The alternative — silently reporting nothing found — is the exact failure this whole design exists to prevent.

04 — scope exclusions

The part most tools leave out is the part worth owning.

Excluded from the scope of this inspection mandatory · may not be empty
  1. whether the chosen design is the right one
  2. whether error messages are good enough for an end user
  3. whether an added benchmark is a fair one
  4. whether the code is understandable to someone who did not write it
  5. whether a test asserts the behaviour it claims to assert

A contract that checks dependencies and green tests will pass a change that is compliant and strategically wrong. That is not a defect in the gates. It is what deterministic means.

So the gap is not an absence — it is a required, dated, owned artefact, and every run prints it. An empty list is a warning, because an empty list is a contract claiming more than it delivers.

This is the difference between a tool you run and a tool you rely on, and it is the one a product page has no incentive to advertise.

05 — nonconformity record

Four defects, all found by running the instrument on real work.

In every case a correct-looking value produced a confidently wrong answer. A failing gate is noticed. A gate that reports no change because it could not read anything looks exactly like a pass. None of the four was found by reading the code.

NCR-001silent

Documented items read as unchanged

A comment stripper matched // inside ///, then hunted for a block-comment close in a line comment, swallowing every documented declaration in the file. The API gate reported no change — correctly, given what it was handed, and completely silently.

Corrective action An empty signature is now unconstructible: the parser refuses outright, so the value cannot exist. One enforcement point is a convention; a second independent one is a defence.

NCR-002silent

A file split read as mass test deletion

A merge where one file became a module moved 17 tests between files. The gate saw one file lose its tests and reported all 17 deleted. Verified: 17 before, 17 after, none deleted.

Corrective action A test's identity is its module path, and not its file. A test that moved has not been deleted; a test that exists nowhere has.

NCR-003silent

A third-party tool's findings were discarded

slop-gate reports its findings and exits 0 at warning level. Branching on the exit code alone dropped every one. The first live run absorbed zero findings from a tool that had one, and printed ACCEPT.

Corrective action A tool's exit code is a statement about the tool, never about the code it inspected. Output is now parsed on both paths.

NCR-004silent

A gate vanished from its own report

The delegated gate was stamped with a hard-coded id rather than the one the contract declared, so the report's ordering pass dropped it. No error, no finding, a verdict that looked earned.

Corrective action Runs now carry the declared id, and the report fails loudly if a declared gate produces no run.

06 — limitations of this report

What this inspection does not establish.

Stated on the record, not in a footnote

  • No independent review exists. Every finding was judged by the person who wrote the gate that produced it. Whether a maintainer finds them tolerable is the one question a self-run corpus cannot answer.
  • Nobody outside the author has run this. 103 of the 240 merges are other people's code and the one substantive defect was external — but unfamiliar code is not an independent opinion, and no third party has adopted the contract.
  • 240 merges across nine repositories with merge history (a tenth contributes rules but has no merge commits), generated contracts. Zero ERROR. Zero blocking-severity false positives. Every finding was advisory.
  • One substantive defect found: a merge that silently dropped four tests, in a repository whose own contribution guide says every PR must pass its checks.
  • checks_green is unmeasured on anything large. It runs cargo test --workspace; on a 38-member crate that is minutes per merge.

The most valuable thing a trial can report is a gate somebody switched off. Silence is the failure mode this instrument is most vulnerable to, and it looks exactly like success.

Why this section exists A product page has every incentive to bury this. An inspection report has none — a report that claims to be complete, without stating what it did not cover, is the defect the whole instrument was built to catch.

07 — requesting an inspection

Three fields.

install
$ cargo install --git https://github.com/origo-labs/rulebound rulebound-cli
issue form
$ rulebound init
inspect
$ rulebound check
note
Every gate is written at warn. The form proposes; it does not judge. Nothing blocks until a gate is promoted to error and the reason is recorded.

In continuous integration.
